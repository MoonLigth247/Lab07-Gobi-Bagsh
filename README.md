## Хэсэг E: Дүгнэлт (debrief)

Хамгийн үр дүнтэй нь Couch Potato аялал байв: хоосон, хязгаараас гадуурх, давхардсан оролтоор BUG-01, BUG-02, BUG-03-ыг олсон. Supermodel (GUI) аялалаар хүснэгт ба тоолуурыг ажиглаж BUG-04 (тоолуур үргэлж 1-ээр илүү) болон BUG-05 (урт гарчигт хүснэгт эвдрэх)-ыг, Saboteur (API) аялалаар curl ашиглан BUG-06 (буруу JSON-д 200 OK)-г олсон. Тоолуурын зөрүү, валидаци, HTTP статус код нь charter-т орсон чиглэлүүд тул эдгээр нь төлөвлөсөн хүрээндээ олдсон. Charter-аас гадуур, оны утга хүснэгтэд таслалтай (1,971; 2,008) харагдаж, «Устгах» товч ногоон өнгөтэй байгаа нь скриншотуудад харагдаж байсан ч би эдгээрийг тусдаа согог болгож тайлагнаагүй. Шалгагдаагүй үлдсэн нь хайлт (том/жижиг үсгийн ялгаа), тусгай тэмдэгт ба XSS, хуудасны линкүүд тул дараагийн session-ий charter эдгээрт чиглэнэ. Лаб 1-ийн Playwright автомат тестээр BUG-01, BUG-02, BUG-03 амархан баригдах байсан: хоосон болон хязгаараас гадуурх оролт оруулаад хүснэгтэд мөр нэмэгдсэн эсэхийг шалгахад хангалттай. BUG-04 нь «Нийт ном» тоог хүснэгтийн мөрийн тоотой харьцуулах нэг assertion-оор, BUG-06 нь хариуны HTTP статусыг шалгах нэг шалгалтаар баригдана. Харин BUG-05 (хүснэгт дэлгэцээс хальсан зохион байгуулалт) нь ихэнхдээ хүний нүдээр илрэх, автоматаар барихад visual regression эсвэл өргөн хэмжих тусгай шалгалт хэрэгтэй. Мөн таслалттай оны формат, ногоон «Устгах» товч зэрэг харагдах байдлын зөрүүг хүн л анзаардаг. Нэг session-д exploratory тест нь автомат тестийн анхнаасаа бичээгүй хэсгүүдийг илрүүлж, харин автомат тест дахин ажиллуулахад хямд байдаг тул хоёулаа хэрэгтэй.
